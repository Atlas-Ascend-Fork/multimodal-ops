3. 融合方案演变

起点：半融合基线（--init-impl，avg=4.56x）

HBM(input+weight) → L1 → L0A/L0B → K1 Cube(矩阵乘) → L0C → fixpipe → HBM(wsT)
                                                              ↓ 中间结果经 HBM 一次往返
                                    HBM(wsT) → UB → K2 Vector(sigmoid) → HBM(output)

两个独立 kernel，各自满流水，中间经 HBM 一次往返。性能好（4.56x）但不是真融合。

iter0-iter1：真融合首版（avg=2.55x）

HBM(input+weight) → L1 → L0A/L0B → Cube(matmul) → L0C → FIX(L0C→UB直通) → Vector(sigmoid) → HBM(output)
                                ↑ 单 @pl.jit kernel，零 HBM 中间读写 ↑

L0C→UB 片上直通（DAV_3510 新特性），wsT 已删除。但 per-tile Cube↔FIX 串行同步导致大 shape 慢。

iter7 最终方案：真融合 + gconv + HF32 + 多 tiling 变体（avg=2.87x，24/24 达标）

核心数据流不变（单 kernel 真融合，零 HBM 中间读写），在此基础上：

  • gconv G-buffer：host 预排列紧凑 G-buffer 消除 case_10 的 81% 零填充（K链 50→6，MTE2 -82%）
  • HF32 变体：fp32 case 用 fp16 matmul + fp32 累加，Cube 吞吐 4 倍提升
  • KB128_TM128：co tile 64→128，tiles 减半（case_3 MTE2 -25%）
  • TP128/TP256/TW128：空间维度 tiling 变体族，fp16/bf16 大 shape 优化
  • 2-deep→3-deep 流水线：ev4/ev5/ev6 多缓冲，隐藏 FIX 搬运延迟
